# ClaudeClaw v1.8.0

ClaudeClaw now supports native OpenAI models alongside Claude.

Each agent can use its own provider and model, so a single ClaudeClaw install can
run a mixed fleet of Claude and OpenAI agents. This release also introduces live
response streaming, improved runtime controls, cross-provider coordination, and
stronger permission enforcement.

> **Before you upgrade, two things will bite you if you skip them:**
> 1. **Run `npm run migrate` before restarting.** ClaudeClaw refuses to start with
>    a pending migration, and under a process manager like PM2 that means a restart
>    loop until you migrate. Migrate first, then restart.
> 2. **Streaming turns on automatically** for every install on upgrade, including
>    Claude-only ones. Set `STREAM_STRATEGY=off` to keep the previous batched view.

## Highlights

### Native OpenAI support

OpenAI is now a first-class ClaudeClaw provider. Agents authenticate using either
an existing `codex login` or an `OPENAI_API_KEY`.

The Codex SDK transport is the default and the rollback path. For persistent
OpenAI sessions with real incremental text streaming, tool progress, cancellation,
compaction telemetry, and policy verification, enable the App Server transport:

```dotenv
CODEX_TRANSPORT=app-server
```

Return to the default SDK transport with:

```dotenv
CODEX_TRANSPORT=sdk
```

The experimental `acp-codex` provider is separate from this native OpenAI
integration and is not required.

### Mixed-provider agent fleets

Each agent can independently run on Claude or OpenAI. Use Claude for some roles and
OpenAI for others while keeping the same Telegram, Dashboard, mission, scheduling,
memory, and coordination surfaces. Provider and model identity are resolved per
turn, so agents do not rely on stale conversational memory to identify themselves.

### Live response streaming

Streaming is now enabled by default. ClaudeClaw displays assistant text as it
arrives, the current tool or work activity, an elapsed-time indicator during longer
turns, and completed activity in a compact turn ledger.

OpenAI App Server provides real incremental assistant-text streaming. The SDK
transport remains supported but may deliver completed assistant messages rather
than token-level updates. Disable the streaming interface with `STREAM_STRATEGY=off`.

### Improved model and runtime controls

The model catalog and runtime controls have been refreshed across Telegram and the
Dashboard, with consistent behavior:

- Same-provider model changes apply to the next turn.
- Provider changes and reasoning/thinking changes require `/newchat`.
- `/model reset` restores the provider default.
- Agent cards show the selected model and only the controls that model supports.
- Unsupported controls are omitted instead of displaying invalid state.

### Cross-provider missions and scheduling

Claude and OpenAI agents coordinate through the same orchestration layer. Depending
on the caller's authorization, agents can create and receive missions, schedule
recurring work, and write operational updates to the Hive Mind. Cross-agent Hive
Mind reads remain opt-in:

```dotenv
DISPATCH_ALLOW_HIVE_READ=true
```

Dispatch authorization is enforced before work reaches the provider, so a
restricted caller cannot gain additional authority through the model runtime.

### Dashboard and Windows reliability

- Responsive, consistently sized agent cards with controls based on real model
  capabilities.
- No more unnecessary restart prompts for ordinary model changes.
- Codex background turns no longer open temporary command windows.
- Agent CLIs resolve repository configuration from outside the checkout directory.
- Existing unquoted Windows `CLAUDECLAW_CONFIG` paths are safely migrated.
- Unknown agent names fail cleanly instead of creating partial missions.

## Security and permissions

The native OpenAI provider uses shared ClaudeClaw capability profiles with
provider-specific enforcement. The runtime verifies the effective App Server
sandbox before each turn, rejects both permission escalation and silent permission
reduction, keeps read-only and tool-less callers isolated, disables shell execution
and web search unless explicitly authorized, exposes only approved MCP servers, and
authorizes dispatch before provider execution.

### Write access by platform

The shipped default remains:

```dotenv
CODEX_DANGER_WRITE=false
```

On macOS, Linux, and WSL2 this allows eligible agents to use contained
workspace writes. Native Windows currently cannot provide the same contained
`workspace-write` sandbox, so trusted native-Windows agents that require writes
must explicitly enable:

```dotenv
CODEX_DANGER_WRITE=true
```

This grants unrestricted machine access and should only be used for trusted private
agents. Use WSL2 when contained Windows-hosted writes are required.

## Upgrade

From the repository root:

```bash
git pull
npm install
npm run migrate
npm run build
```

Then restart your services. **Migration runs before restart** (see the callout at
the top). The v1.8.0 migration only quotes legacy unquoted Windows
`CLAUDECLAW_CONFIG` paths, leaves quoted / macOS / Linux values alone, and writes
`.env.pre-v1.8.0.bak` first.

Optional: set `CLAUDECLAW_OWNER_NAME` so shared surfaces label you correctly. Fresh
setup fills this from the wizard; existing installs set it by hand:

```dotenv
CLAUDECLAW_OWNER_NAME=Michael
```

## Validation

Validated with the full automated test suite, Codex schema compatibility checks,
SDK rollback testing, live App Server turns, model and reasoning-effort switching,
provider switching across multiple agents, streaming and tool progress, thread
resume and `/newchat`, turn-scoped cancellation, crash recovery without prompt
replay, concurrent different-thread turns, serialized same-thread turns, compaction
and context telemetry, missions/schedules/memory ingestion/plugin calls, a
16-child four-join mixed-provider fleet run, and native Windows runtime operation.

## Known limitations

- Native Windows cannot currently provide contained Codex writes. Use trusted
  `CODEX_DANGER_WRITE=true` access or run under WSL2.
- Voice / War Room voice mode is experimental and its current Python
  runtime/environment work is deferred to a post-release update. Text-based
  interaction is unaffected.
- Dependency security findings are tracked for a focused patch release rather than
  forcing breaking dependency upgrades into this validated release.
- App Server remains opt-in while the SDK stays the default and rollback path.
