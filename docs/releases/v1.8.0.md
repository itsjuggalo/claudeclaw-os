# v1.8.0: Claude and Codex, one fleet

**Theme:** Run any agent on OpenAI (Codex) instead of Claude, or mix both in one fleet, with live streaming on by default.

**Bundles:** #174.

---

> ## 🚨 v0 release of Codex support
> Native OpenAI (Codex) ships as a **v0**. It is ready for early use, but it is new and environment-sensitive. Follow the setup steps closely, and if you run several agents, move **one** agent to Codex first and exercise it before switching the rest.

---

## Highlights

**🤖 ClaudeClaw runs on OpenAI now, not just Claude.**
Any agent can run on a GPT model through Codex instead of Claude. Keep some agents on Claude, put others on Codex, or mix both in the same fleet, and they still share the same Telegram, dashboard, missions, scheduling, memory, and coordination. Two ways to connect: the default SDK transport, or the opt-in App Server transport for real incremental streaming.

**🎚 Switch agents one at a time.**
Provider and model are set per agent in `/dashboard`, under Agents (for each sub-agent) or Settings (which controls your **primary agent only**). There is no fleet-wide switch on purpose. Move one agent to Codex, test its conversations, tools, permissions, and scheduled work, then roll out to the rest.

**⚡ Live responses are on by default.**
You see the answer as it is written, with a live progress line and an elapsed clock, instead of waiting on a blank screen. App Server gives true token-level streaming; the SDK transport still works but may deliver the whole reply at once. Set `STREAM_STRATEGY=off` to go back to the old batched view (Telegram sends text only when the turn completes).

**🎛 Refreshed model catalog and per-agent controls.**
The selectable model list and runtime controls are refreshed across Telegram and the dashboard, so picking the right model per role is simpler. Same-provider model changes apply next turn; provider or reasoning changes take a `/newchat`.

**🔒 Provider-aware permissions.**
Tool permissions are enforced per provider with a shared policy, so a Codex agent and a Claude agent follow the same rules. Dispatch is authorized before work reaches the model, and the App Server sandbox is verified before every turn (it fails closed in both directions).

---

## 🛠 Upgrading? Two required steps

1. **Run `npm install` and `npm run migrate` before restarting.** ClaudeClaw refuses to start while a migration is pending, and under a process manager like PM2 that means a restart loop until you migrate. Migrate first, then restart.
2. **Streaming turns on automatically** for every install on upgrade, including Claude-only ones. Set `STREAM_STRATEGY=off` to keep the old batched view.

The v1.8.0 migration only quotes legacy unquoted Windows `CLAUDECLAW_CONFIG` paths, leaves quoted / macOS / Linux values alone, and writes `.env.pre-v1.8.0.bak` first.

# Details

## Native OpenAI support

OpenAI is now a first-class ClaudeClaw provider. Agents authenticate using either an existing `codex login` or `OPENAI_API_KEY`.

The Codex SDK transport remains the default and the rollback path. For persistent OpenAI sessions with incremental text streaming, tool progress, cancellation, compaction telemetry, and policy verification, enable the App Server transport:

```dotenv
CODEX_TRANSPORT=app-server
```

Return to the default SDK transport with:

```dotenv
CODEX_TRANSPORT=sdk
```

The experimental `acp-codex` provider is separate from this native OpenAI integration and is not required.

## Mixed-provider agent fleets

Each agent can independently run on Claude or OpenAI. Use Claude for some roles and OpenAI for others while keeping the same Telegram, Dashboard, mission, scheduling, memory, and coordination surfaces. Provider and model identity are resolved per turn, so agents do not rely on stale conversational memory to identify themselves.

## Live response streaming

Streaming is now enabled by default. ClaudeClaw displays assistant text as it arrives, the current tool or work activity, an elapsed-time indicator during longer turns, and completed activity in a compact turn ledger.

OpenAI App Server provides real incremental assistant-text streaming. The SDK transport remains supported but may deliver completed assistant messages rather than token-level updates. Disable the streaming interface with `STREAM_STRATEGY=off`.

## Improved model and runtime controls

The model catalog and runtime controls have been refreshed across Telegram and the Dashboard, with consistent behavior:

- Same-provider model changes apply to the next turn.
- Provider changes require `/newchat`.
- Reasoning-effort or thinking changes require `/newchat`.
- `/model reset` restores the provider default.
- Agent cards show the selected model and only the controls that model supports.
- Unsupported controls are omitted instead of displaying invalid state.

## Cross-provider missions and scheduling

Claude and OpenAI agents coordinate through the same orchestration layer. Depending on the caller's authorization, agents can create and receive missions, schedule recurring work, and write operational updates to the Hive Mind. Cross-agent Hive Mind reads remain opt-in:

```dotenv
DISPATCH_ALLOW_HIVE_READ=true
```

Dispatch authorization is enforced before work reaches the provider. Restricted callers cannot gain additional authority through the model runtime.

## Dashboard improvements

- Responsive, consistently sized agent cards.
- Model and reasoning controls based on actual model capabilities.
- Provider details that stay aligned with the Agent panel.
- Clearer `/newchat` guidance for thread-scoped changes.
- No unnecessary restart prompts for ordinary model changes.
- Improved behavior when resizing the browser or on narrow screens.

## Windows reliability improvements

- Codex background turns no longer open temporary command windows.
- Agent CLIs resolve repository configuration from outside the checkout directory.
- Existing unquoted Windows `CLAUDECLAW_CONFIG` paths are safely migrated.
- Unknown agent names fail without creating partial missions.
- Canonical agent aliases resolve consistently across mission and scheduling commands.

## Security and permissions

The native OpenAI provider uses shared ClaudeClaw capability profiles with provider-specific enforcement. The runtime now:

- verifies the effective App Server sandbox before each turn
- rejects both permission escalation and silent permission reduction
- keeps tool-less and read-only callers isolated
- disables host applications and account enumeration for restricted callers
- disables shell execution when the caller does not permit it
- keeps web search disabled unless explicitly authorized
- exposes only approved MCP servers
- authorizes dispatch before provider execution
- interrupts only the intended App Server turn during cancellation

### Write access by platform

The shipped default remains `CODEX_DANGER_WRITE=false`. On macOS, Linux, and WSL2 this allows eligible agents to use contained workspace writes.

Native Windows currently cannot provide the same contained `workspace-write` sandbox. Trusted native-Windows agents that require writes must explicitly enable:

```dotenv
CODEX_DANGER_WRITE=true
```

This grants unrestricted machine access and should only be used for trusted private agents. Use WSL2 when contained Windows-hosted writes are required.

## Owner identity

Fresh setup now stores the owner name collected by the setup wizard, providing a deterministic owner label in shared surfaces such as text War Room conversations. Existing installations can set it manually:

```dotenv
CLAUDECLAW_OWNER_NAME=Michael
```

## Validation

This release was validated with the complete automated test suite, Codex schema compatibility checks, SDK rollback testing, live App Server turns, model and reasoning-effort switching, provider switching across multiple agents, streaming and tool progress, thread resume and `/newchat`, turn-scoped cancellation, crash recovery without prompt replay, concurrent different-thread turns, serialized same-thread turns, compaction and context telemetry, missions/schedules/memory ingestion/plugin calls, a 16-child four-join mixed-provider fleet run, and native Windows runtime operation.

## Known limitations

- **Codex is v0** and environment-sensitive; follow the setup steps and pilot one agent before rolling out across a fleet.
- Native Windows cannot currently provide contained Codex writes. Use trusted `CODEX_DANGER_WRITE=true` access or run under WSL2.
- Voice / War Room voice mode remains experimental; its current Python runtime/environment work is deferred to a follow-up. Text interaction is unaffected.
- Dependency security findings are tracked for a focused patch release rather than forcing breaking dependency upgrades into this validated release.
- App Server remains opt-in while the SDK stays the default and rollback path.
